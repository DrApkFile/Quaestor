## Not done / known problems

- C1 does not establish Groth16 soundness, metadata privacy (the memo board is public, recipient hints are visible), or browser behaviour. The payer is an authorized second recipient; the claim explicitly identifies that self-copy.
- Separate-process/key loading is demonstrated by the worker code and recorded PIDs; this is not an OS-level filesystem sandbox. All demo account files remain local to the builder's test environment.
- Script journals store plaintext note secrets locally with owner-only permissions. Browser storage, encrypted backup and browser interception tests remain M6 work. Do not publish .accounts/.
- Worker failure checkpoints preserve public scan errors and native-window/receipt observations. A partial failed worker is not automatically replayed: inspect held operations before retrying; workers require fresh receiver journals. Unknown broadcasts stay held and are resolved by stored hash, never rebuilt.
- Preserve .accounts/m2/ privately, including the business's new 1-QOR change note. Successful evidence reruns retain the existing result and do not send again.
- QoreSeal 0.1.0 itself depends on QoreSign 0.1.0 internally; our direct QoreSign pin is 0.2.0. The actual card signing/verification with SDK-account keys was tested offline and against Diana's registered keys.

The current lint step has no workspace lint tasks; Forge reports no contract tests. The gate's real 35 tests and forbidden-path check do not claim those missing checks exist.

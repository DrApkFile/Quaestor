Written by Claude, 2026-11-20, after M0 closed. Read `AGENTS.md` first, then this brief, then `briefing/knowledge/gloam.md` and `briefing/knowledge/qorechain-evm-pqc.md`. When you finish, write `docs/handoff/M1.md` from `docs/handoff/TEMPLATE.md` and stop.

## Goal
From TypeScript, on QoreChain testnet, using our deployed pool: **shield → private send to a second account → that account unshields.** Every step a real transaction, recorded in `evidence/m1-roundtrip.json`.

## Build
1. **`packages/chain`** (TypeScript strict, ESM, `tsconfig.base.json`), with exact pins: `@gloamtrade/sdk 0.8.0`, `@qorechain/sdk 0.14.0`, `@qorechain/evm 0.14.0`, `viem 2.58.2`, `snarkjs 0.7.6`, `zod`.
   - `config.ts`: zod-validated config (addresses above, RPC/REST, deploy block). No defaults that hide a missing value.
   - `accounts.ts`: load a role's account from `.accounts/` (scripts only; the web app will have its own account store).
   - `window.ts`: read `/qorechain/pqc/v1/evm_window/{qor1}` with `evmWindowStatus`; open with `openEvmWindowMsg` + `EthNativeSigner` hybrid broadcast, copying the pattern in `tools/evm-window/scripts/window.ts`. Return a discriminated result; `WINDOW_CLOSED` when not live.
   - `pqcKey.ts`: register an account's ML-DSA-87 key (same pattern as `window register`: classical-signed `buildRegisterPqcKeyMsg` with proof of possession). The client and supplier accounts need this before they can send any EVM tx.
   - `prover.ts`: snarkjs `groth16.fullProve(..., { singleThread: true })` over the self-hosted circuits in `apps/web/public/circuits/` (shield, transfer, unshield). Return `{ proofBytes: packGroth16Proof(proof), publicSignals }`.
   - `tree.ts`: `createTreeSync(publicClient, { pool, fromBlock: 10427515n, chunkSize })` — page logs; if the RPC caps the range, lower `chunkSize` and record the cap in REALITY_SPIKES S07.
   - `pool.ts`: thin wrapper that turns SDK intents into transactions:
     - `shield`: `buildShieldBoundIntent({ chainId: 9800, poolAddress, asset, amountWei, prover, client })` → send `exec` (fn `shieldBound`, `valueWei` for native) → wait for receipt → persist `intent.note` **before** broadcasting (journal) and mark it `OWNED` only after the receipt and after the commitment appears in the synced tree.
     - `privateSend`: `pathForCommitment(note.commitment)` → `buildPrivateSendIntent({ chainId: 9800, poolAddress, secretHex, amountInWei, amountPayWei, asset, path, prove })` → send `exec` → `paymentNote` goes to the payee (in M1, write it to the payee's local note store; in M2 it becomes a PQ ticket) and `changeNote` stays with the sender.
     - `unshield`: `buildUnshieldIntent({ ..., to, client })` → send → receipt.
     - Use the ABI from forge's build output (`contracts/out/ShieldPoolPayments.sol/ShieldPoolPayments.json`) or the SDK's exported fragments; never hand-write selectors.
   - `journal.ts`: JSON-file journal for scripts (the browser gets IndexedDB in M6). States `PLANNED → PROVED → BROADCAST → LANDED`, plus `OUTCOME_UNKNOWN`. A spend in `BROADCAST` or `OUTCOME_UNKNOWN` is never rebuilt; resolve by tx hash.
2. **`scripts/m1-roundtrip.mjs`** (or `.ts` with tsx): uses `packages/chain` to
   1. register ML-DSA-87 keys for `business` and `supplier1` if missing;
   2. open a window for `business` (txs: 2, value: the deposit + fees) and `supplier1` (txs: 1);
   3. `business` shields **5 QOR** (native; fUSD conversion is S13 and comes after);
   4. `business` privately sends **2 QOR** to `supplier1` (payment note handed over locally);
   5. `supplier1` unshields its 2 QOR to its own EVM address;
   6. writes `evidence/m1-roundtrip.json`: every tx hash, block, gas, the commitments and nullifiers, the root used, balances before/after for `supplier1`, and timestamps. **No secrets** (no note secrets, no keys) in evidence.
3. **S13 (fUSD)**: after the QOR round trip passes, try `MsgConvertCoin` for 100 fUSD on `business` (bank coin `erc20:0x9714…63CA` → ERC-20) and read `balanceOf`. Record the result in REALITY_SPIKES S13 whatever happens. Don't build the fUSD path further in M1.

# M2 brief: post-quantum payment tickets

Supplied by the builder after Claude approved M1 and M1-fixes, 2026-11-20.

## Goal

Replace “payment note handed over in a local file” with a real post-quantum ticket. When the business pays supplier1 privately, the note supplier1 needs is sealed with QoreSeal hybrid (ML-KEM-1024 + X25519) to supplier1’s QoreChain-registered key, posted on our memo board 0xD6131645AB115D589Cc059A6207E127fC3d88545, found and opened by supplier1, checked against the pool tree, then spent.

Pins: @qorechain/qoreseal 0.1.0, @qorechain/qoresign 0.2.0 (exact).

## Build in packages/chain (or a new packages/tickets if cleaner)

### sealKeys.ts

- deriveSealKeys({ mnemonic, index: 0 }) from the account’s own mnemonic (scripts only; never from a wallet signature).

### kemRegistry.ts

- Register the ML-KEM-1024 key with buildRegisterKemKeyMessage({ sender, mlkemPublicKey }), hybrid-signed through the existing broadcastNative. Map failures with describeKemRegistryError plus the retained code, codespace and rawLog.
- Read keys with fetchKemKey / fetchMlkemPublicKey, pinned to one height where the REST endpoint supports it.
- Idempotent: if the registered key already equals ours, do nothing. If a different key is registered, return KEM_KEY_MISMATCH and never overwrite silently.

### card.ts

- Sign with signRecipientCard, using the SDK account’s keys as in S15.
- Save to cards/<qor1>.json in the repo. Cards are public data; assert no secret fields.
- Verify with verifyRecipientCard against the on-chain ML-DSA-87 key (/qorechain/pqc/v1/account/{addr}, possession proven) and the on-chain ML-KEM key. Any failure is CARD_INVALID, never a fallback to mlkem mode.

### ticket.ts (the codec; pure, no network)

- Plaintext = canonical JSON of the payee’s note { v: 1, secret, commitment, nullifier, amountWei, asset, pool, chainId: 9800 }.
- seal({ chainId: "qorechain-diana", purpose: "quaestor:ticket", recipients: [payee, payerSelf], plaintext, aad }), with AAD = UTF-8 "9800|<pool lowercase>|<paymentCommitment lowercase>".
- Refuse mode: "mlkem", anonymous envelopes and anything over 8,192 bytes.
- Never import Gloam’s sealToReceiveTag, openSealedTicket, receiveTag.ts or any P-256/ECDH code.

### memoBoard.ts

- Post with postMemo(paymentCommitment, ticketBytes), using the ABI from forge output (contracts/out/GloamPayMemo.sol/GloamPayMemo.json), through the existing gateway, journal and estimated gas.
- Scan the memo events from the board’s deploy block (from evidence/m0-deploy.json) in pages.
- For each memo, try open with the payee’s seal keys and the AAD rebuilt from the event’s commitment. NOT_A_RECIPIENT means skip silently; any other error is recorded with its code.
- After opening, require the note’s commitment == the event’s commitment and the commitment is in the pool tree at a pinned block. Otherwise TICKET_INVALID.

### Journal and executor

- Payment state becomes … LANDED → TICKET_POSTED (PRD §10).
- The payee’s note becomes OWNED only after its ticket is opened and checked, not from the payer’s journal.
- The sender keeps its change note.
- Payer and payee use separate journals (.accounts/m2/<role>.json), so the handover really goes through the chain.

## Script pnpm evidence --m2

1. Register ML-KEM keys and publish cards for business, supplier1 and auditor (the auditor is used in M3). Record their tx hashes.
2. business shields 5 QOR (or reuses its M1 change note if it is still unspent), then privately pays supplier1 2 QOR.
3. Seal the ticket to supplier1 plus the business’s own copy, and post it.
4. In a fresh process with only supplier1’s journal and keys, scan the board, open the ticket, verify it, and unshield the 2 QOR.
5. Show that the client account (which has a KEM key registered in this run, but is not a recipient) scans the same memo and is refused (NOT_A_RECIPIENT).
6. Write evidence/m2-ticket.json: every tx hash; the KEM key SHA3-256 values; card hashes; ticket size, envelope mode and recipient count; the memo tx hash; supplier1’s open result and tree check; the client’s refusal code. Never include plaintext, secrets or keys.

## Tests (vitest)

T-TICKET-NO-CLASSICAL-FALLBACK (no P-256 import anywhere in our packages; a test greps for it) · ticket ≤ 8,192 B · outsider refused · wrong AAD refused · card signed by another key → CARD_INVALID · stale card (KEM key changed) → CARD_INVALID · memo for a commitment not in the tree → TICKET_INVALID · payee note OWNED only after open + tree check.
